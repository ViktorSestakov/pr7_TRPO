# Практическая работа № 7 — WPF-клиент для Pet API

Приложение на .NET 8 / WPF с Material Design 3. Выполняет все операции из задания через `HttpClient`. Данные, форма, состояние загрузки и сообщения связаны с интерфейсом через Data Binding. В code-behind только создание ViewModel, запуск загрузки и освобождение ресурсов.

## Как запустить

1. На Windows установите Visual Studio 2022 с компонентом **«Разработка классических приложений .NET»** и .NET 8 SDK.
2. Запустите свой ASP.NET Core API из предыдущей практической работы с приложенным `PetController` и настроенной базой данных.
3. Откройте `pr7_shestakov.sln`, дождитесь восстановления NuGet-пакетов и нажмите F5.
4. В верхнем поле укажите **адрес запущенного сервера** из его `Properties/launchSettings.json` или консоли. Например, `http://localhost:7193/`. Не добавляйте `api/v1/Pet`: клиент добавляет этот маршрут сам.
5. Нажмите **«Подключиться / обновить»**. При старте приложение также пытается загрузить список по адресу из исходной заготовки: `http://localhost:7193/`.

Если сервер работает по HTTPS, укажите именно `https://` и его HTTPS-порт. Для локального сертификата разработки при необходимости выполните `dotnet dev-certs https --trust` в проекте API. Проверка сертификатов в клиенте включена.

Сервер и база данных запускаются отдельно: в этом репозитории находится клиент для приложенного контроллера. Адрес можно менять в окне без пересборки приложения.

Сборка из терминала на Windows:

```powershell
dotnet build pr7_shestakov.sln --configuration Release
dotnet run --project pr7_shestakov.csproj
```

## Реализованные действия

| Действие в интерфейсе | Запрос к API |
| --- | --- |
| Подключиться / обновить | `GET /api/v1/Pet` с уже применёнными фильтрами |
| Применить фильтры вида и статуса | `GET /api/v1/Pet?species=...&adopted=true/false` |
| Сбросить фильтры | `GET /api/v1/Pet` без параметров |
| Выбрать строку | Показать копию записи в форме |
| Получить по ID | `GET /api/v1/Pet/{id}`, в том числе для записи вне текущего фильтра |
| Новая → Создать питомца | `POST /api/v1/Pet` |
| Сохранить полностью (PUT) | `PUT /api/v1/Pet/{id}` со всеми пятью полями |
| Только изменения (PATCH) | `PATCH /api/v1/Pet/{id}` только с изменёнными полями |
| Удалить питомца → подтверждение | `DELETE /api/v1/Pet/{id}` |

Поле **«Вид»** фильтруется на сервере точным сравнением, как в `PetController`: вводите значение в том же написании, что в базе. Статус имеет три варианта: без фильтра, `adopted=false` и `adopted=true`. Текстовые параметры кодируются для URL. Для сохранения списка используются применённые фильтры; изменение текста фильтра вступает в силу после нажатия «Применить».

После успешного POST, PUT, PATCH или DELETE список заново загружается с сервера. Если запись перестала соответствовать фильтру, она исчезает из списка. Пустые тела ответов `201 Created`, `200 OK` и `204 No Content` поддерживаются: POST и PATCH в приложенном контроллере не возвращают JSON.

В форме проверяются обязательные имя и вид, целочисленный неотрицательный возраст, положительный вес и положительный ID для поиска. Вес допускает запятую и точку (`4,5` / `4.5`); в JSON отправляется число. Неверные значения не уходят на сервер. Кнопки и поля блокируются на время запроса; запросы асинхронные. Есть сообщения о недоступном сервере, тайм-ауте 15 секунд, HTTP-ошибках и неверном JSON. Если запись сохранилась, а обновление списка не удалось, приложение сообщает об этом отдельно.

## Структура

- `Models/Pet.cs` — поля модели из API: `id`, `name`, `species`, `age`, `weight`, `isAdopted`.
- `Services/PetApiClient.cs` — HTTP-запросы, сериализация и обработка ответов.
- `ViewModels/MainViewModel.cs` — команды, список, фильтры и состояние окна.
- `ViewModels/PetEditor.cs` — копия редактируемой записи, валидация и вычисление PATCH.
- `Infrastructure/` — `INotifyPropertyChanged` и асинхронная реализация `ICommand`.
- `MainWindow.xaml`, `App.xaml` — привязки и оформление Material Design.

## Проверки

Проверки HTTP-контракта и ViewModel используют подставной HTTP-обработчик / API и не требуют запущенной базы данных. Они проверяют маршруты, методы, типы JSON, оба значения фильтра `adopted`, частичное обновление, пустые ответы, ошибки и обновление интерфейса после операций:

```powershell
dotnet run --project tests/PetClient.Tests/PetClient.Tests.csproj --configuration Release
```

Проверка реального WPF-окна на Windows загружает ресурсы Material Design, отслеживает ошибки привязок и сохраняет PNG двух состояний окна:

```powershell
dotnet run --project tests/WpfSmoke/WpfSmoke.csproj --configuration Release -- artifacts
```

GitHub Actions запускает сборку и обе проверки на Windows. Артефакт `pet-client-windows` содержит скриншоты и папку `app` с собранным клиентом. Для запуска опубликованного `pr7_shestakov.exe` требуется .NET 8 Desktop Runtime для Windows.

Для итоговой проверки со своей базой: создайте питомца, найдите его по ID, примените фильтры, сохраните все поля через PUT, измените одно поле через PATCH и удалите запись с подтверждением. Затем остановите API и нажмите обновление — в окне должно появиться понятное сообщение, а приложение должно продолжить работу.
